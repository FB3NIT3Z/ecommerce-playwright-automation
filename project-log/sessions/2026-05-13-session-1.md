## 🐛 Issues Encountered

Technical problems faced during this session:

### Issue 1: Product Sorting Selector Timeout

- **Description:** Tests TC024, TC025, TC026 failing with timeout error when trying to select sorting dropdown options
- **Error Message:** `TimeoutError: page.selectOption: Timeout 10000ms exceeded`
- **Impact:** 3 tests failing (sorting tests), blocking Phase 1 completion
- **Time Lost:** ~15 minutes debugging
- **Solution:** Changed from `page.selectOption('[data-test="..."]', 'value')` to `page.locator('select.product_sort_container').selectOption('value')`
- **Root Cause:** Using deprecated/incorrect selector syntax
- **Prevention:** Use modern `.locator()` chain consistently
- **Reference:** [Issue #001](../issues/001-sorting-selector-fix.md) *(to be created)*

**Debugging Process:**
1. Read error message and stack trace
2. Checked Playwright documentation
3. Examined screenshots from test failure
4. Tried different selector strategies
5. Found working solution with class selector
6. Verified fix across all browsers

## 📚 Key Learnings

New knowledge gained today:

### 1. **Playwright Auto-Waiting is Powerful**
- **What:** Playwright automatically waits for elements to be actionable before interacting
- **Why it matters:** Eliminates need for explicit waits, makes tests more stable
- **Example:** `await page.click('#button')` waits automatically - no `waitFor` needed
- **Practical impact:** Zero flaky tests in entire suite

### 2. **Locator Strategy Matters**
- **What:** Modern `.locator()` method is more reliable than legacy methods
- **Why it matters:** Better chaining, more stable selectors
- **Example:** `page.locator('select').selectOption('value')` > `page.selectOption()`
- **Practical impact:** Solved the sorting selector issue immediately

### 3. **Feature-Based Organization Scales Well**
- **What:** Organizing tests by feature (auth, cart, checkout) instead of by type
- **Why it matters:** Easier to find, modify, and maintain related tests
- **Example:** All authentication tests in `01-authentication/` folder
- **Practical impact:** Could navigate and add tests quickly

### 4. **Multi-Browser Testing is Simple**
- **What:** Playwright config makes cross-browser testing trivial
- **Why it matters:** Catches compatibility issues early
- **Example:** Just add projects array in `playwright.config.ts`
- **Practical impact:** All 23 tests work perfectly on 3 browsers

### 5. **Learning Without POM First is Valuable**
- **What:** Starting with direct page interactions before adding abstraction
- **Why it matters:** Understand fundamentals before adding complexity
- **Example:** Will appreciate POM benefits more in Phase 2 after experiencing maintenance
- **Practical impact:** Solid foundation in Playwright basics

### 6. **Documentation System Pays Off**
- **What:** Creating structured project-log from day 1
- **Why it matters:** Portfolio-ready, helps learning retention, professional
- **Example:** Can show detailed progress in interviews
- **Practical impact:** 30 minutes upfront saves hours later
