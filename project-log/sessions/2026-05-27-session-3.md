## 📚 Key Learnings

### 1. Multi-Site Testing Configuration
**What:** Configure Playwright to test multiple applications in one framework  
**How:** Use `testMatch` regex patterns and site-specific `baseURL`  
**Why important:** Scalable architecture for enterprise test frameworks  
**Reference:** playwright.config.ts lines 63-140

### 2. Professional Project Organization
**Pattern:**
```
pages/{sitename}/
tests/{sitename}/
```
**Benefits:** Clear separation, easy to add new sites, no naming conflicts  
**Industry standard:** Used in multi-application test suites

### 3. Selector Strategy Varies by Site
**Sauce Demo:** Primarily `[data-test]` attributes  
**The Internet:** Mix of IDs, classes, and element types  
**Lesson:** Always inspect actual HTML before writing locators

### 4. Cross-Browser Testing Reality
**Ideal:** 100% pass rate on all browsers  
**Reality:** Browser-specific issues exist (network, timing, rendering)  
**Professional approach:**
- Document issues thoroughly
- Make pragmatic decisions based on browser market share
- Choose stable configurations for CI/CD

### 5. When to Accept Known Issues
**Criteria:**
- Low severity and low priority
- Browser market share is minimal (Firefox ~3%)
- Tests pass on primary browsers (Chromium 70%, Safari 20%)
- Issue is environmental, not functional
- Time investment vs. value trade-off
