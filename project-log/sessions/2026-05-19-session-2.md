## 🐛 Issues Encountered

Technical problems faced during this session:

### Issue 1: EADDRINUSE Error when opening report
- **Description:** When running `npx playwright show-report` got error `EADDRINUSE: address already in use ::1:9323`
- **Impact:** Could not visualize the HTML report
- **Solution:** Identified the process using port 9323 with `lsof -ti:9323` and closed it with `kill [PID]`
- **Reference:** Common error when there are multiple instances of the report server

### Issue 2: Timeout in sorting test
- **Description:** Test TC044 was failing with timeout when trying to select dropdown option. The selector `[data-test="product_sort_container"]` couldn't find the element
- **Impact:** 1 out of 28 POM tests was failing consistently
- **Solution:** Reviewed original Phase 1 tests and found that the correct selector is `select.product_sort_container` (CSS class instead of data-test attribute)
- **Reference:** tests/04-sorting/product-sorting.spec.ts line 22

## 📚 Key Learnings

New knowledge gained today:

1. **Page Object Model Pattern**
   - What: Design pattern that encapsulates page elements and actions in a TypeScript class
   - Why it matters: Improves maintainability (changes in one place), code reusability, and more readable tests
   - Reference: pages/LoginPage.ts, pages/InventoryPage.ts, pages/CartPage.ts, pages/CheckoutPage.ts

2. **Data-Driven Testing with forEach**
   - What: Technique to execute the same test with multiple data sets using arrays and forEach
   - Why it matters: Reduces code duplication and allows testing multiple scenarios with minimal effort
   - Reference: tests/pom/data-driven.spec.ts

3. **Difference between data-test attributes and CSS selectors**
   - What: Not all elements have `data-test` attribute, some only have CSS classes
   - Why it matters: It's important to verify the actual HTML or use Playwright Inspector to identify correct selectors
   - Reference: Correct selector for dropdown: `select.product_sort_container`
